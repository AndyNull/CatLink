## 1. 结论

微信小程序采用原生 TypeScript、WXML、WXSS 和微信官方组件/API，单独建设客户端架构，复用现有 Go 服务端、MySQL、Redis、对象存储和管理端。

业务目标不是把 Android Compose 页面机械翻译为 WXML，而是在微信运行约束下保持同一账号、同一公开内容、同一社区关系和同一档案业务规则。Android 专属的 Room、WorkManager、Keystore、SSE、系统分享和文件备份必须替换为小程序实现。

第一版按“公共能力先行、私密档案后接入”发布：先完成游客可用的公开猫咪、社区和页面框架，微信登录暂缓；随后再接入消息、AI、用户中心及可跨端恢复的私密档案、领养、合同、回访与同步。这样避免登录阻塞前端开发，也避免在密钥兼容方案未验证前破坏 Android 已有加密资料。

## 3. 腾讯官方规范基线

计划以腾讯官方文档为约束，不采用浏览器网页容器模拟 App。

- [小程序开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/)：使用小程序框架、组件和 API。
- [小程序配置](https://developers.weixin.qq.com/miniprogram/dev/framework/config.html)：通过 `app.json` 管理页面、窗口、TabBar 和网络超时。
- [网络使用说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)：请求、上传、下载只访问后台配置的 HTTPS 域名；域名需 ICP 备案；生产环境不得依赖跳过域名校验。
- [小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)：客户端用 `wx.login` 获取一次性 code，服务端调用 `code2Session`，`session_key` 只保存在服务端。
- [分包加载](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html)：主包/单分包不超过 2 MiB，全部分包不超过 30 MiB。
- [隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)：后台声明所处理的信息，隐私接口调用前完成协议提示与同意同步。
- [微信小程序设计指南](https://developers.weixin.qq.com/miniprogram/design/)：页面重点单一、流程明确、导航可退、局部加载反馈、减少输入、避免误触并预留右上角胶囊区域。
- [开发者工具命令行](https://developers.weixin.qq.com/miniprogram/dev/devtools/cli.html)：使用 CLI V2 或 `miniprogram-ci` 完成预览、构建、自动化和上传。

必须执行的工程约束：

- 生产请求域名、上传域名和下载域名全部使用有效 HTTPS 证书与备案域名。
- `AppSecret`、微信 `session_key`、AI Key、对象存储密钥只在服务端环境变量中存在。
- 主包只放启动、五个 Tab 页面壳、登录态和公共组件；重页面进入分包。
- 基础库版本在首次开发时以当期稳定版确定，不在计划书中硬编码未来版本。
- 涉及头像、昵称、相册、相机、位置、剪贴板等能力时，后台隐私声明与代码调用保持一致。
- 页面同时只显示一个主要加载反馈；错误必须就地说明并提供可恢复动作。

## 4. 技术选型

### 4.1 客户端

| 项目 | 选择 | 原因 |
|---|---|---|
| 框架 | 原生微信小程序 | 与腾讯规范、审核和平台能力保持最短链路 |
| 语言 | TypeScript | 提供 API 契约、页面状态和领域模型静态检查 |
| 模板/样式 | WXML + WXSS | 不引入跨端运行时和额外包体 |
| 组件 | 微信原生组件；必要时使用官方 WeUI Miniprogram | 保持交互一致和可访问性 |
| 状态 | 页面局部状态 + 轻量全局 store | 不引入重量级状态框架 |
| 网络 | 封装 `wx.request`、`wx.uploadFile`、`wx.downloadFile` | 统一 Token、错误码、取消和重试策略 |
| 缓存 | `wx.setStorage` 保存会话、ETag、游标和小体积草稿 | 小程序仅做缓存，不把本地缓存当事实源 |
| 测试 | 纯函数单测 + 微信自动化 + API 契约测试 | 覆盖逻辑、页面流程和端到端接口 |

不选择 Taro、uni-app、React/Vue 运行时。当前只有微信目标，额外框架会增加包体、调试层和平台差异，收益不足。

### 4.2 服务端

- 继续使用 `catlink-admin-next/backend` 作为唯一 Go API。
- 继续复用 MySQL、Redis、对象存储、审核后台和现有 `/api/v1` 契约。
- 新增微信身份适配层，不单独建设云开发数据库，不复制业务数据。
- 账号 Token 仍使用现有 Access/Refresh Token 体系；微信 code 只负责证明微信身份。
- 小程序请求增加 `X-Client-Platform: wechat-miniprogram`、客户端版本和幂等键，便于审计与灰度。

## 7. 身份与账号架构

### 7.1 微信登录

```text
小程序 wx.login()
  -> POST /api/v1/auth/wechat/login { code, clientId, deviceName }
  -> 服务端 code2Session
  -> 查找或创建 external_identity(provider=wechat_miniprogram, subject=openid)
  -> 签发现有 Access Token / Refresh Token
  -> 小程序仅保存自有 Token，不保存 session_key
```

服务端新增：

- `POST /api/v1/auth/wechat/login`：微信 code 登录。
- `POST /api/v1/account/bind/email`：登录后绑定既有邮箱账号。
- `POST /api/v1/account/bind/wechat`：邮箱登录后绑定当前微信身份。
- `DELETE /api/v1/account/bind/wechat`：满足二次验证条件后解绑。
- `cat_external_identities`：`provider`、`subject_hash`、`union_id_hash`、`account_id`、时间和审计字段。

唯一约束为 `(provider, subject_hash)`；OpenID/UnionID 只保存不可逆检索哈希或加密值，不写日志。一个微信身份不能绑定多个业务账号，账号合并必须通过显式验证流程。

### 7.2 登录策略

- 游客可浏览公开猫咪、社区公开内容和公开用户主页。
- 发布、关注、收藏、评论、私信、举报、档案和 AI 必须登录。
- 首次微信登录创建轻量账号；需要跨端同步 Android 私密档案时，再验证并绑定原邮箱账号。
- 不强迫用户授权头像或昵称。用户可使用微信头像选择组件，也可手工设置公开资料。
- Refresh Token 轮换、设备撤销和并发会话规则继续复用现有实现。

## 8. 数据与同步架构

### 8.1 公共数据

公开猫咪、社区、用户、通知、私信和 AI 全部以服务端为事实源。小程序只缓存：

- 当前账号与短期会话状态。
- 列表首屏、游标、筛选条件和 ETag。
- 未提交的帖子/评论/档案表单草稿。
- 图片本地临时路径，不持久保存为业务记录。

应用进入前台、下拉刷新和完成写操作后进行增量刷新；不得依赖后台常驻同步。

### 8.2 私密档案

Android 当前使用本地 Room + 客户端加密 Vault。小程序无法直接复用 Android Keystore，也不能把 `wx.setStorage` 当数据库，因此必须先完成跨端密钥与数据兼容验证。

确定方案：

1. 复用现有 Vault 记录格式、实体类型、revision、tombstone 和冲突协议。
2. 用户绑定原邮箱账号后，通过现有恢复码/密码信封解锁同一 DEK。
3. 小程序内存中解密当前会话所需数据，持久缓存只保存密文和最小索引。
4. 新增服务端分页拉取或按实体聚合接口，避免每次发送完整 Vault。
5. 写操作携带 `baseRevision` 和幂等键；冲突进入可读的选择流程，不执行静默覆盖。
6. 删除继续使用 tombstone；公开投影必须在同一服务端事务中归档。

在浏览器/真机完成 WebAssembly 或纯 TypeScript AES-GCM、PBKDF2/HKDF、随机数和大数据性能验证前，不开放小程序私密档案写入。若基础库加密能力无法满足现有协议，则将私密档案延后，不能改为服务端明文保存。

### 8.3 小程序存储边界

- 不在本地长期保存合同正文、领养人联系方式、精确位置或完整相册。
- 敏感页面退出时清理明文状态；退出账号时清空账号级缓存。
- 图片上传成功后释放临时文件引用。
- 缓存必须带账号命名空间，禁止 A 账号读取 B 账号残留。

## 9. API 改造计划

### 9.1 必需新增

- 微信登录、绑定、解绑接口及外部身份表。
- `GET /api/v1/bootstrap`：聚合品牌、地区版本、媒体限制、账号摘要和功能开关。
- Vault 分页增量接口，或扩展现有 `/vault/sync` 支持小批量游标同步。
- 小程序订阅消息登记接口：保存用户主动授权的模板和业务事件，不保存多余微信数据。
- AI 非流式响应接口；若后续验证分块传输稳定，再启用逐段渲染。
- 海报所需短链/小程序码服务端接口，避免客户端持有平台 access token。

### 9.2 直接复用

- `/community/*`、`/public/cats/*`、`/users/*/public`。
- `/conversations/*`、`/account/notifications*`。
- `/media/upload`、`/media/content/*`、`/share/*`、`/reports`。
- `/leaderboards/*`、`/location/*`、`/regions*`、`/encouragements/random`。
- `/ai/cat-profile` 以及现有账号资料、设备和 Token 接口。

### 9.3 契约规则

- 所有列表采用游标分页，避免在小程序一次加载全部数据。
- `wx.request` 收到 HTTP 响应即会进入成功回调，客户端必须自行判断 `statusCode` 和业务码。
- 上传按队列控制并发，远低于平台 10 个网络请求上限。
- 所有写接口接受 `Idempotency-Key`；发布、评论、上传和同步可安全重试。
- 错误返回稳定业务码与可显示文案，不向客户端返回 SQL、GORM、对象存储或微信 API 原始错误。
- 媒体 URL 使用配置过的下载域名，不返回 IP、localhost 或显式 `:443`。

## 10. 微信能力替代关系

| Android 实现 | 小程序实现 |
|---|---|
| Room 本地数据库 | 服务端事实源 + 小体积缓存 + 加密 Vault 密文缓存 |
| WorkManager 后台同步 | 前台生命周期增量同步 + 手动下拉刷新 |
| Android Keystore | 微信会话内存 + 恢复码/密码信封；不持久化明文 DEK |
| SSE 常驻通知 | 前台轮询/短连接；业务提醒使用用户主动授权的订阅消息 |
| 系统 Photo Picker | `wx.chooseMedia`，调用前完成隐私协议与声明 |
| Android 分享面板 | `onShareAppMessage`、`onShareTimeline`、海报保存 |
| 本地 1080×1920 海报 | Canvas 2D 生成并经用户操作保存到相册 |
| 本地 ZIP 导入导出 | 服务端异步导出申请；微信内下载/转发只作为辅助 |
| 本地通知 | 小程序订阅消息或应用内待办 |
| 精确定位 | 用户触发后调用位置接口；公开内容只上传区县级信息 |

## 11. UI 与交互标准

- 保留有猫腻现有品牌、三套主题和信息层级，不复刻 Compose 组件代码。
- 使用微信原生导航和 TabBar，所有二级页面可明确返回。
- 自定义导航时读取胶囊位置并预留安全区，不在右上角布置主操作。
- 表单尽量使用选择器、日期、地区和标签，减少键盘输入。
- 建档、发帖等长表单分段保存草稿；错误就地标记具体字段。
- 列表默认骨架或局部加载，不使用全屏模态加载覆盖普通请求。
- 删除、解绑、永久清空等不可逆动作使用明确确认框。
- 点击区域按平台标准组件尺寸设计，避免图标过密和小热区。
- 图片列表使用缩略图与懒加载，原图只在预览时下载。
- 字体和布局支持系统字号及不同屏宽；真机至少覆盖窄屏、主流屏和大字号。

## 12. 隐私、安全与审核

### 12.1 隐私

- 管理后台填写《小程序用户隐私保护指引》，声明实际使用的头像、昵称、相册、相机、位置、剪贴板等信息类型。
- 启动时查询隐私授权状态；只有触发相关能力时才展示协议与申请权限。
- 精确位置默认不采集；附近功能优先使用用户选择的城市/区县。
- 帖子与公开猫咪发布前剥离 EXIF/GPS；合同、联系方式和内部备注不可进入公开副本。
- 隐私政策更新后重新验证新增接口对应的同意状态。

### 12.2 安全

- `AppSecret` 和平台 access token 只存在服务端环境变量与密钥管理系统。
- 服务端校验所有 OpenID 绑定、资源所有权、角色、媒体归属和可见范围。
- 文件上传校验 MIME、扩展名、文件头、大小、像素和内容审核结果。
- 社区文本与图片进入现有审核、举报、下架和申诉闭环。
- 日志记录请求 ID、账号 ID、平台和业务动作，不记录 Token、code、OpenID 明文、session_key、私密档案正文。
- 接口按 IP、账号、设备和业务动作限流；登录、验证码、发帖、评论、私信和 AI 单独限额。
- 生产环境关闭跳过域名/TLS 校验选项，并在 iOS、Android 微信真机验证。

- 小程序版本与后端能力通过 feature flag 解耦，服务端可关闭单个高风险写功能。

## 17. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| Vault 加密协议在小程序性能不足 | 私密档案无法安全跨端 | 先只读验证；不通过则私密档案延期，不降级为明文 |
| 现有生产域名未备案或证书不合规 | 真机请求全部失败 | 阶段 0 先完成域名与证书验收 |
| 微信身份与邮箱账号重复 | 数据分裂或账号占用 | 显式绑定、唯一约束、二次验证、禁止隐式合并 |
| 五 Tab 挤压窄屏 | 可用性下降 | 真机验证文字宽度；不增加第六入口 |
| 包体超过 2 MiB | 无法上传或启动慢 | 主包最小化、分包、图片外置、每次构建检查 |
| 订阅消息不能替代常驻推送 | 提醒到达率变化 | 应用内通知为事实源，订阅消息只做增强 |
| Android API 偏本地模型 | 小程序请求过重 | 增加分页增量与聚合接口，不复制业务逻辑到客户端 |
| 社区内容审核不足 | 审核与运营风险 | 复用现有审核、举报、下架、申诉和审计闭环 |

## 18. 回滚方案

- 小程序版本通过微信后台回退到上一稳定版本。
- 所有新功能受服务端 feature flag 控制，可单独关闭写入、AI、Vault 或订阅消息。
- 数据库迁移采用向前兼容的新增表/列，首发阶段不删除旧字段。
- 微信身份表与现有账号表分离；关闭微信登录不会影响 Android 邮箱登录。
- 小程序 Vault 写入启用前先灰度到测试账号；发生协议问题时立即切回只读。
- API 保留至少一个小程序版本的兼容窗口，服务端先发布、客户端后启用。
